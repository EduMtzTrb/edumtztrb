## Architecture Decision

Nine standalone components under `src/components/media/` (`Figure.tsx`, `Caption.tsx`, `GallerySequence.tsx`, `ComparisonPair.tsx`, `ComparisonMatrix.tsx`, `DocumentPlate.tsx`, `VideoFrame.tsx`, `ArtworkViewer.tsx`, `ProductMediaSet.tsx`), plus one shared stylesheet (`src/styles/media.css`). No `<Media variant="figure|gallery|comparison|...">` mega-component and no nine unrelated visual systems — instead, **`Figure` is the genuine foundational primitive that six of the other eight compose directly**: `ArtworkViewer`, `VideoFrame` (passing a configured `<video>` as `media`), `GallerySequence`, `ComparisonPair`, `ComparisonMatrix`, `DocumentPlate`, and `ProductMediaSet` all render one or more real `<Figure>` elements internally rather than reimplementing figure/caption structure. `Caption` is itself a small shared primitive both `Figure` and (indirectly, through `Figure`) every other primitive reuses. This is composition, not inheritance or a variant switch — each outer component still owns its own distinct DOM shape, ARIA role, and props; only the innermost "media + optional caption/credit" structure is shared code.

## Shared Media Invariants

Every primitive:

- accepts arbitrary media as a prop (`media`, or an `items`/`first`/`second` array/object of `{ media, ... }`) — never assumes the child is a photograph; an `<img>`, `<video>`, a drawing rendered as an inline SVG, or a plain fixture `<div>` are all equally valid.
- preserves intrinsic media proportion — no `aspect-ratio`, no `object-fit`, no `object-position` anywhere in `media.css` (asserted by `media-contract.test.ts`).
- applies no default frame/plane/card/shadow (the one documented exception is `DocumentPlate`'s `.frame`).
- never gates essential information (media itself, caption, credit) behind hover — `media.css` contains no `:hover` rule at all (asserted by contract test).
- uses only already-resolved typography/spacing/color/geometry tokens — no new token minted, no hard-coded color, no new spacing scale (every `gap`/`margin`/`padding` in `media.css` is either `0` or a `var(--space-*)` reference, asserted by contract test).
- introduces no theatrical motion — no `transform`, `transition`, or `animation` property anywhere in `media.css`.
- is not a district-specific component — no `WorkFigure`/`LabGallery`/etc. exists.

## Figure

`src/components/media/Figure.tsx` — the foundational primitive (§11 of this task's own scope). Renders a real `<figure>` (never a `<div>` pretending to be one), a `.media-figure-slot` wrapping the supplied `media` unmodified, and an optional `Caption` (rendered as a real `<figcaption>`) when `caption` and/or `credit` is supplied. `ariaLabel` exists for the rare case a figure needs an accessible identity beyond its own caption text (exercised by `VideoFrame` and `ArtworkViewer`, both of which pass it through). No mandatory frame/background/radius/crop. Works identically for a photograph, drawing, diagram, render, screenshot, or any other visual artifact — nothing in the component or its tests assumes "image."

## Caption

`src/components/media/Caption.tsx` — quiet, media-attached text (§42, §12's type table). Defaults to rendering a real `<figcaption>` (`as="figcaption"`); `as="p"` is available for the rare case a caption is needed outside a `<figure>` context (not currently used by any M2.8 primitive, since all nine ultimately place their captions inside a real `<figure>` via `Figure`, but kept as a documented, tested escape hatch rather than a hard-coded assumption). Applies `.type-caption` (M2.2) — no new typeface, no default Mono. `credit`, when supplied, renders as a second, structurally distinct segment within the same element (an em-dash-separated span) rather than a new typography size, since §42/§12 explicitly give caption and credit one shared role, not two.

## Gallery Sequence

`src/components/media/GallerySequence.tsx` — an ordered set of media with a stable reading order (§13 of this task's own scope, §45's "sequencing" as one of the ways a relationship stays understandable). A plain `<ol aria-label>` of `<li>`-wrapped `Figure`s — not a carousel: every item is present in the DOM simultaneously (asserted by test — `toBeVisible()` on every item, not just the "active" one), no gesture-only interaction, no hidden essential information. Each item carries an explicit `"n / total"` position indicator (`.type-metadata`) next to its caption, satisfying "optional position/count" without requiring interactive navigation the current authority doesn't call for.

## Comparison Pair

`src/components/media/ComparisonPair.tsx` — meaningful visual comparison between exactly two items (§14, §45). A `role="group" aria-label={label}` wrapping two `Figure`s, each captioned with its own item-level `label`. The relationship stays legible through labels and stable spatial correspondence alone — no drag-to-reveal slider, no assumption the two items share dimensions (`records.css`-style flex layout: `flex: 1 1 280px` on each side, recomposing side-by-side → stacked at narrow widths via ordinary wrapping, not a breakpoint override).

## Comparison Matrix

`src/components/media/ComparisonMatrix.tsx` — more than two comparable items on shared axes (§15, §45). A `role="group" aria-label={label}` CSS grid (`repeat(auto-fit, minmax(200px, 1fr))`) of `Figure`s — recomposes its column count as the viewport narrows rather than shrinking cells to illegibility, and never wraps items in a generic card (no `.plane`/`.frame`/`.card` anywhere). Alignment and gap carry the structure, consistent with the border rule's "spacing before containment."

## Document Plate

`src/components/media/DocumentPlate.tsx` — a PDF page, drawing sheet, research document, technical artifact, or scanned page (§16, §38.1 lists documents among crop-resistant, extent-carrying media). The **one M2.8 primitive that legitimately applies `.frame`** (M2.4) by default: a document genuinely has an extent worth marking, which this task's own §9/§16 explicitly calls out as a legitimate Frame use case — every other primitive in this package stays unframed (asserted by `media-contract.test.ts`, which scans every other component's source for a stray `.frame`/`.plane` className). ## Video Frame

`src/components/media/VideoFrame.tsx` — native `<video>` semantics (§17, §43). `controls` is always present; default playback is user-initiated (`autoPlay` defaults to `false`). §43 permits autoplay only when audio is absent/muted — enforced **at the type level**, not just by convention: the props type is a discriminated union where `autoPlay: true` requires `muted: true` in the same object, so a silently-autoplaying-with-audio video is a compile error, mirroring the enforcement style M2.5 already established for `Action`'s `iconOnly`/`aria-label` pairing. No custom transport controls are built — native `<video controls>` already provides accessible, keyboard-operable playback that M2.5's action semantics would only duplicate. An optional captions track (`captionsSrc`/`captionsLabel`) renders only when actually supplied — no fabricated empty `<track>`. Internally delegates to `Figure` for its outer figure/caption/credit structure, passing the configured `<video>` element as `media`.

## Artwork Viewer Shell

`src/components/media/ArtworkViewer.tsx` — the strongest media-authority rule in this package (§18, §40: "Artwork receives the strongest protection from interface competition"). Deliberately a thin wrapper around `Figure` — `media`, `caption`, `credit`, and `ariaLabel` pass straight through — with one visual difference: `className="media-artwork-viewer"` applies more generous void (`padding-block: var(--space-8)`, the same token M2.7's `PortalRecord` already uses for its own "more void than other records" posture) instead of `Figure`'s default zero-margin tightness. Caption/credit recede in visual weight (via the same `.media-caption`/`color: var(--color-mist-300)` every other primitive already uses — no new muting mechanism) but are never hover-gated (§41's "credits may not exist only on hover," verified by test).

## Accessibility

- **No inferred alt text:** no M2.8 component generates or infers alternative text — that responsibility belongs entirely to whatever media element the consumer passes as `media` (e.g., `<img alt="...">`). This is a deliberate, documented constraint (§20 of this task's own scope), not an oversight.
- **Informative vs. decorative vs. complex media** remains the consumer's call, made on the child element itself (`alt="..."` vs. `alt=""` vs. a longer adjacent `caption`) — M2.8 primitives provide the structural place for that information (the slot, the caption, the credit) without dictating its content.
- **Accessible naming enforced at the type level where structurally possible:** `GallerySequence`, `ComparisonPair`, `ComparisonMatrix`, `ProductMediaSet`, and `VideoFrame` all require a `label`/`label`-equivalent prop (not optional) — a grouping/video primitive with no accessible name at all is a compile error, mirroring M2.5's `Action` `iconOnly`/`aria-label` enforcement pattern.
- **Real semantic grouping:** `role="group"` on `ComparisonPair`/`ComparisonMatrix`, real `<ol>` for `GallerySequence`/`ProductMediaSet` (order is semantically meaningful, so a list is correct, not a generic `<div>` stack).
- **Video captions:** `VideoFrame`'s optional `captionsSrc`/`captionsLabel` render a genuine `<track kind="captions">` when supplied (§63's "video speech receives captions") — never a fabricated empty track.
- **Video autoplay/audio safety:** enforced at the type level (see **Video Frame** above), directly implementing §43.
- **No nested-interactive violations:** the only interactive element any M2.8 primitive renders is native `<video controls>` (inside a `<figure>`, never inside a link or button) — nothing here duplicates or conflicts with it.
- **No hover-only information:** captions/credits always render in the DOM; `media.css` contains no `:hover` rule at all.
- **Fixtures clearly marked:** every test uses unmistakable fixture strings ("Fixture …") — never anything resembling real portfolio/product content.

## Responsive Behavior

No fixed pixel width and no viewport-specific media query exists in `media.css` — every family recomposes through ordinary flex/grid wrapping rather than a breakpoint override:

- **Figure** — the slot is `width: 100%`, so it naturally fills whatever width its container (a record, a page section) provides at any size; intrinsic media proportion is preserved throughout.
- **Gallery Sequence** — a single-column flex stack at every width; reading order is unaffected by viewport.
- **Comparison Pair** — `flex-wrap: wrap` with `flex-basis: 280px` per side naturally goes side-by-side on wide viewports and stacks on narrow ones without a breakpoint.
- **Comparison Matrix** — `repeat(auto-fit, minmax(200px, 1fr))` recomposes its column count continuously as width changes, down to a single column on narrow viewports, rather than shrinking cells below a legible minimum.
- **Document Plate** — `.frame` and the plate identifier/caption all sit inside ordinary block flow; the plate fits available width without a forced fixed size.
- **Video Frame** — `.media-video { width: 100%; height: auto }` preserves intrinsic aspect ratio at every width.
- **Artwork Viewer** — same `Figure`-based full-width slot, with generous fixed-token padding (not viewport-scaled) preserving proportional void at any size.
- **Product Media Set** — same single-column flex stack as Gallery Sequence, so evaluation order survives narrow viewports unchanged.

Full breakpoint-by-breakpoint (`~390`/`~768`/`~1024`/`~1440–1600px`) verification against real rendered content is deferred to the human visual round (no browser tool available) and, eventually, M2.12's full responsive-system verification — this package only establishes a defensible responsive foundation, per this task's own instruction not to perform that full audit early.
