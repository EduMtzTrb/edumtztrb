## Grouping

## Canonical Record

`/work/[entry]` performs a real M3.1 registry lookup for the first time — previously a string-interpolated placeholder. `findWorkRecord` checks `allFixtureDistrictRecords` first (for the richer `WorkExtension` — context/contribution/process/outcome) then falls back to `allFixtureRecords`; `isDirectlyAccessible` (M3.1's own included+not-private rule) gates the result, so the excluded/private `fixtureUnpublishedWorkRecord` correctly renders `UnavailableState`, never leaking private content, and an unknown slug does the same. A resolved record populates every `CanonicalRecordShell` region it actually has data for — `evidence` (summary, plus extension fields when present), `metadata` (`MetadataRail`: content type, status, date, role), `relationships` (`RecordTrace`, only when real relationships exist), `credits` (only when collaborators exist) — never an invented placeholder for a region with no data (M1.5's own optional-region contract, unchanged).
