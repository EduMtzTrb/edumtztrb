## Calibration Implementation

Root cause and reasoning for the first human review's findings, and the composition-only fixes applied — no canonical ownership, data, or M3/M4 architecture changed anywhere in this pass.

### Root cause

Two structural facts, found by auditing the existing shared systems rather than by guessing at a visual fix:

1. **The curated highlight was placed in `DistrictField`'s `peripheral` zone.** `district-composition.css` (M5.0, unmodified by this pass) makes `.district-field-peripheral` *permanently* carry peripheral latency — dimmed color (`--color-mist-300`) and reduced opacity (`--opacity-latent`) — by design, for genuine annotation. That is exactly correct for a closing "Return to Home" link and exactly wrong for "curated professional foreground": the previous overview was structurally guaranteed to render its one real record as visually recessive, no matter what content it held. This is finding A/B's mechanical cause.
2. **`CanonicalRecordShell` (`src/components/page-shells/CanonicalRecordShell.tsx`) has carried zero CSS of its own since M1.5.** Every region (`context`/`evidence`/`metadata`/`relationships`/`credits`/`continuation`) was a bare `<section>`, a full-width grid child of `.composition` with no spacing, no divider, and no lateral structure between them — only the header's own `.field-interval` had any deliberate void. That is finding D's mechanical cause: a large, correct threshold void followed by an undifferentiated stack of paragraphs, because nothing downstream of the header had ever been styled at all (M1.5 explicitly deferred "final typography, responsive grid... content-driven layout" — this pass is the first to give the shell's own regions real treatment).

### Overview changes (`src/app/work/page.tsx`)

- The curated highlight (title, orientation, real metadata, real relationship trace) moved from `peripheral` into `primary`, wrapped in a new `.curated-highlight` rhythm primitive (below) — it now reads with full resolved color authority, the same authority the thesis text has, not a dimmed annotation.
- `peripheral` now carries exactly one thing: the "Return to Home" departure link — genuinely the sequence's closing "Crossroads" wayfinding action (WORK_UNIVERSE_v1.1.md §10), correctly the one element that should stay latent.
- The highlight now uses `fixtureWorkRecordWithExtension` (still the same one real fixture, `fixture-work-001`, just the richer `WorkRecord` shape) so a real `MetadataRail` (content type, role) can render beside the record — the same metadata vocabulary the canonical record page already uses, not new data.
- The thesis sentences kept their exact approved text but dropped from `type-body-large`/`type-body` to `type-body`/`type-body` — a small, deliberate reduction in their own typographic weight, so authority visibly shifts toward the now-resolved evidence beside them, per the review's "should not be dominated by those sentences."
- A new "Selected Work" eyebrow label (WORK_UNIVERSE_v1.1.md §11's own term) sits above the highlight, giving the curated block its own identified role in the sequence, distinct from the thesis above it.

### Curated-foreground changes

Addressed entirely through the overview change above plus one new, generic, reusable primitive — `.curated-highlight` (`src/styles/canonical-record.css`) — internal rhythm only (spacing + one leading hairline separating it from the thesis text above); it sets no color, so the block inherits full resolved-layer authority from its `primary`-zone context rather than from any new palette. `PortalRecord` (M2.7, unmodified) remains the record primitive in use — audited against building a bespoke Work card per the task's own instruction, and rejected: the recessiveness was entirely a placement/zone problem, not a component-capability problem, so no new component was needed.

### Comprehensive-view changes (`/work/all`)

- `IndexResults`/`IndexRecord`/`queryIndex` (M3.10) are completely unchanged — no second archive mechanism, no new fields rendered, no district-scoped fork of the shared row primitive.
- One real, honest sentence — "Comprehensive access — every publicly discoverable Work record, scannable by content type and date." — precedes the results, describing the catalogue's actual scan axes (the exact `type`/`date` fields `IndexRecord` already renders) so the architecture reads as established even with the current single fixture row.
- `index-results.css`'s `.index-result-list` gained one universal (not district-scoped) leading hairline + rhythm — a semantic separator marking where the scannable catalogue itself begins, the same hairline idiom used everywhere else in this pass. This applies identically to every Index/Search/comprehensive/grouping consumer platform-wide, not only Work.
