## Research vs Work

Three concrete, deliberate implementation differences (not incidental — each is reasoned and documented at its own point of use):

1. **Curated view filter.** `/work/selected` filters on `featured === true` — an editorial curatorial judgment WORK_UNIVERSE_v1.1.md §11 explicitly reserves for the platform owner ("Selected Work is an editable curatorial state, not a permanent ranking"). `/research/current` filters on `lifecycle === "active"` — a state-based read of the district's own real activity, matching RESEARCH_UNIVERSE_v1.1.md §7's own text ("research lines currently receiving attention... the active edge of the knowledge structure") and PLATFORM_SPECIFICATION.md §5.4's own deliberate route name ("Current," not "Selected"). Neither fabricates a curatorial judgment; they use two different real fields because the two districts' universes define "curated/current" differently. Consequence: the one real Research fixture (`lifecycle: "active"`) genuinely appears at `/research/current`, while Work's `/work/selected` remains honestly empty (no fixture is `featured`) — a real difference in outcome, from real data, not a styling difference.
2. **Evidence hierarchy.** Work's canonical record gives Outcome `type-body-large` — real resolved-result emphasis, because Work resolves and demonstrates. Research's canonical record gives no field that treatment. RESEARCH_UNIVERSE_v1.1.md §11 is explicit: "the interface must never make a hypothesis look like a verified result." Research's Question (the framed inquiry — "questions before claims," same section) and Position (the current, self-consciously provisional interpretation) both stay at ordinary `type-body` weight — Question sits in `.evidence-primary` for spatial priority (asked before Context/Methods/Evidence/Uncertainty), Position deliberately sits in `.evidence-supporting` (the same dimmed Secondary tier `MetadataRail` already establishes) so it visually reads as provisional rather than resolved. The composition itself encodes the epistemic distinction the Universe document requires — not a caption, not a color, not a badge.
3. **Grouping lens.** `/work/practice/[practiceArea]` groups by the `discipline` lens. Research's three fixed grouping routes (Publications/Writing/Talks) instead each map onto one real M3.1 `CanonicalContentType` value (`publication`/`essay`/`talk-or-presentation`) via the `content-type` lens, and `/research/themes/[theme]` uses the `theme` lens — a different real dimension for a genuinely different organizational need (Research's own approved vocabulary is publication format and subject matter, not practice discipline).

None of this touches "shared logic" in M3.8's sense — the overview → curated → grouping → comprehensive *ordering* is identical across every district; only the real field each stage filters on differs, exactly the class of content-shaping decision M5.2 already established is a route's own to make.
