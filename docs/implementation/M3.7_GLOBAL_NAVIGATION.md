## Known deferred defect — responsive wrapping — resolution

M2.2 and M2.3's visual reviews both recorded responsive `GlobalNav` wrapping as an adjacent observation, explicitly deferred to M3.7 (`M2.2_TYPOGRAPHY.md` "Adjacent Observation: Responsive Navigation Wrapping"; reconfirmed unworsened by M2.3/M2.4). The underlying issue: `.global-header` was a single `flex-wrap: wrap` row containing both the Primary and Utilities `<nav>` landmarks. At narrow widths, both landmarks' link lists could end up wrapping onto shared/adjacent lines with no structural separation between "district navigation" and "utility navigation" — technically all ten destinations remained present and reachable (no clipping, no hiding), but the wrap boundary between the two semantically distinct landmarks was not deliberate.

**Resolution** (`src/styles/shell.css`), mobile-first and CSS-only:

- **Default (compact) layout**: `.global-header { flex-direction: column; align-items: flex-start; }` — the Primary and Utilities landmarks stack as two unambiguous, separately-wrapping blocks. Each landmark's own `<ul>` keeps its pre-existing `flex-wrap: wrap`, so its own links reflow internally without ever mixing with the other landmark's links.
- **`@media (min-width: 768px)`** — the existing single-row layout (`flex-direction: row`, `justify-content: space-between`) applies, matching the desktop treatment already visually reviewed and left unchanged in M2.2–M2.4.
- `min-width: 0` added to both `<ul>` rules — a standard flexbox correction ensuring a nav landmark can actually shrink to its container's width and wrap internally, rather than a flex item's default `min-width: auto` forcing horizontal overflow.
- `768px` is the already-approved breakpoint value (`M2.3_SPACING_GRID.md`'s grid breakpoint) — no new breakpoint was invented.

No JavaScript, no hamburger/disclosure menu, no hidden-until-tapped state, and no motion were introduced — the task's own instruction to prefer "the smallest system consistent with the existing shell" and not invent "elaborate mobile choreography." All ten destinations (7 districts + 3 utilities) remain simultaneously present in the DOM and visually reachable at every width, exactly as before — only the wrap boundary between the two landmarks is now deliberate instead of incidental.
