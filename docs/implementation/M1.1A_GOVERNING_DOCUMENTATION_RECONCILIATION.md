## Purpose

M1.1 (Repository Audit) found that the repository's governing documentation contained competing versions of the same conceptual documents with no clear active/superseded distinction, plus four newly-arrived documents (`IMPLEMENTATION_PLAN_v1.0.md`, `PLATFORM_SPECIFICATION_v1.0.md`, `DESIGN_SYSTEM_v1.0.md`, `ANIMATION_SYSTEM_v1.0.md`) that were untracked in Git. M1.1A exists to remove that ambiguity — establishing exactly one authoritative version of each governing document, archiving what it supersedes, and recording what still cannot be verified — without changing any approved requirement or any application code.

## Naming and Archive Convention

- **Active files kept their existing filenames** (`DESIGN_SYSTEM_v1.0.md`, `ANIMATION_SYSTEM_v1.0.md`, `PLATFORM_SPECIFICATION_v1.0.md`, `IMPLEMENTATION_PLAN_v1.0.md`, all at repository root). This follows the repository's own existing precedent: the Universe Specification Set's *active* files are also version-suffixed (`docs/universes/HOME_UNIVERSE_v1.1.md`, etc.), not bare (`HOME_UNIVERSE.md`). Renaming the four new files to drop their version suffix would have gone against that established pattern for no disambiguation benefit, since — once the old `DESIGN_SYSTEM.md`/`ANIMATION_SYSTEM.md` were moved out of the way — there was no longer a competing file at any name.
- **Superseded files moved to `docs/archive/proposals/`**, a new directory created for this purpose. No existing archive convention already covered "a single system-level document superseded by a newer version" (the existing `docs/archive/universes/` convention is specific to the seven per-district universe documents and their multi-stage merge/review history, which does not map cleanly onto a single proposal-to-approved document). `docs/archive/proposals/` is a minimal, understandable addition alongside the existing `docs/archive/universes/`.
- **`PLATFORM_SPECIFICATION_v1.0.md` and `IMPLEMENTATION_PLAN_v1.0.md` were left at the repository root**, not moved into `docs/`. There is no competing older version of either document anywhere in the repository, so no ambiguity exists to remove by moving them — doing so would have been a file move with no disambiguation purpose, which this task's instructions caution against ("minimum file moves... required to remove ambiguity").
- **`PLATFORM_VISION.md` and `INFORMATION_ARCHITECTURE.md` were left in place, untouched.** They are Unresolved, not Superseded — nothing has replaced them, so archiving would misrepresent their status. Moving or renaming an Unresolved document was not part of this task's instructions and was avoided.
