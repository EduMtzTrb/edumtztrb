## Focus

`FocusRegion`/`FocusItem` (M4.4, unmodified) are consumed by a real canonical-record page for the first time. The artwork (`ArtworkViewer`, M2.8) plus its always-visible orientation text form `FocusItem`'s `summary` — never hidden, matching ART_UNIVERSE_v1.1.md §5/§13's requirement that the work itself remains the constant. Extended context (artist statement, exhibition context) is `detail`, rendered only while focused — genuine progressive disclosure over real data, never "a zoomed/enlarged copy" of the same content (`FocusItem`'s own documented rule). `recessionToken="--motion-recession-overlay"` — an existing `FocusRegion` configuration knob (M4.4), matching Art's own "strongest interface recession" register (§74) — not a new mechanism.

Only wired when the record actually has real media (`record.media?.[0]`): a future record without media renders the same evidence content without Focus, rather than presenting an interactive control with nothing genuine to reveal. The Focus control is a real, native `<button>` (`aria-expanded`), fully keyboard-operable, never trapping focus or locking scroll (`FocusRegion`'s own documented, unmodified non-modal contract) — matching this batch's own explicit "never become theatrical... no full-screen trap" instruction without adding new code to enforce it, since M4.4 already guarantees it structurally.

With only one real fixture, the "receding siblings" visual effect `FocusRegion` provides for multiple items isn't observable today — the same honest limitation M5.4's Comparison wiring already accepted (the mechanism is real and correctly consumed; full demonstration awaits real multi-record content).

## Media Disclosure

The one real fixture's `media[0]` (`kind: "image"`, real `source`, real `accessibility.altText`/`credit`) renders through a genuine `<img>` inside `ArtworkViewer` — not `next/image` (which would require either a static import or fabricated width/height; `ArtExtension.dimensions` is descriptive text, not real pixel dimensions, and inventing numbers to satisfy `next/image` would itself be a fabrication `Figure`/`ArtworkViewer`'s own "no forced aspect ratio or crop" law, M2.8, explicitly guards against). This adds one new ESLint warning (`@next/next/no-img-element`) beyond the M5.2-closure baseline of 15 — reported honestly in "Validation" below, not suppressed.

Alt text is computed correctly from the discriminated `MediaAccessibilityMetadata` union: `altText` only exists on the `"informative"`/`"complex"` roles; a `"decorative"` role renders `alt=""`, the correct accessibility convention, never a missing/undefined attribute.

The full six-way per-type disclosure table (§17: digital/generative/interactive/performative/ephemeral/process-based) is not implemented — the one real fixture is a static `"live"` image with none of that complexity to disclose. What **is** wired: the shared preservation-state vocabulary (`presentationCondition`), shown honestly in Metadata. Building the full table now, against data that cannot exercise it, would risk exactly the kind of speculative architecture this project's own discipline avoids — deferred explicitly (see "Deferred").
