## Shared orientation model

One module, `src/components/shell/orientation.ts`, providing one `OrientationContext` shape capable of representing every obligation the scope lists: current district, content type, current record/section, parent grouping, active lens, active filter scope (a typed slot only), route to district overview, and route to comprehensive district access. "Relationship to global navigation" is satisfied structurally rather than duplicated: `districtOverviewRoute`/`comprehensiveRoute` are read directly from M3.8's own `DISTRICT_NAVIGATION` table — the exact same data `GlobalNav`/`DistrictNav` already render from, never a second, independently maintained route list.

Three entry points build an `OrientationContext` from different page roles, all producing the same shape:

- `orientationForRecord(record, { parentGrouping? })` — a canonical-record deep entry (M3.13's primary use).
- `orientationForSection({ district, currentLabel, currentHref, parentGrouping?, activeLens?, activeFilterScope? })` — a district-owned deep structure that isn't itself a record: curated view, grouping, archive/comprehensive view.
- `orientationForUtility({ currentLabel, currentHref, activeLens? })` — a global utility (Search, Index, an Index lens route, Contact), which owns no district.

## Breadcrumb semantics

`src/components/shell/Breadcrumb.tsx` — a plain Server Component (no client state) rendering `<nav aria-label="Breadcrumb">` wrapping an `<ol>`, exactly per this task's own §C2. Every non-current item is a real link (`next/link`) to an already-approved route; the current item renders as plain text carrying `aria-current="page"`, **never** a link to itself — `buildBreadcrumbTrail` (in `orientation.ts`) omits `href` for whichever item is current, and `Breadcrumb` renders any item without an `href` as a `<span>`, never an `<a>`.

## Parent grouping

Modeled as `ParentGrouping { label; href? }` — contextual, never canonical ownership (this task's own §C3). `href` is genuinely optional: M3.8's own audit found several grouping families (practice areas, collections, themes, series, medium) dynamic-only with no static index route; a parent grouping without a real destination renders as plain, non-linked text rather than an invented route (tested directly). A record's own resolved canonical route (via M3.3's `resolveCanonicalRoute`, composed inside `orientationForRecord`) is completely unaffected by whichever parent grouping context it's viewed through — canonical identity, not contextual path, per this task's own architecture.

## Active filter / lens boundary

`activeLens`/`activeFilterScope` are typed slots on `OrientationContext`, passed straight through to `buildBreadcrumbTrail`'s caller without any filtering logic — this task's own explicit instruction (§C4) not to implement real filter logic in M3.9. M3.11 (Phase E of this batch) is the package that will give these slots real behavior.

## No universal previous/next

Not implemented, per this task's own explicit instruction (§C5: "do not add universal previous/next... only intentional sequences qualify"). No true sequence content (exhibition, series, research sequence, experiment lineage, ordered collection) exists yet in this repository; adding a generic "next" would have been exactly the "next project" pattern this task forbids.
