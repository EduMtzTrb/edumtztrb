### Compositional Gap Audit

The question this audit answers is not "do the seven page-shell components exist" (they do — see Part A audit item 2) but whether they already share one coherent spatial grammar. They do not. Concretely:

- `.composition` (`src/styles/layout.css`, M2.3) is the platform's one shared 4/8/12 grid, but its own rule `.composition > * { grid-column: 1 / -1; }` makes **every** direct child span the full row — there is no mechanism anywhere in the repository for assigning a primary/peripheral role a different column span. `primitives.css`'s own comment confirms this was left open on purpose: "No content exists yet that needs a narrower span; a future component can opt into one explicitly... once real content requires it."
- `CanonicalRecordShell`'s optional regions (`context`, `evidence`, `metadata`, `relationships`, `credits`, `continuation`) are each rendered as a direct child of `.composition` — so today they all receive the same full-row `grid-column: 1 / -1`, with no shared-axis relationship, no dominant/peripheral distinction, and no density variation between them.
- `DistrictNav` (`src/styles/district-nav.css`, M3.8) used a fixed `padding: var(--space-2) var(--space-4)`, unrelated to `.composition`'s fluid `--margin-compact`/`--margin-medium`/`--margin-wide` tokens — so district navigation's left/right edge did not actually align with the content grid immediately below it. This is the one concrete "district navigation relationship to content" gap named in the compositional audit checklist.
- No mechanism existed for selective offset, density gradients, or peripheral latency anywhere in the codebase — these are DESIGN_SYSTEM.md v1.1 §11 concepts that, before this package, existed only in the Design System document, never in an implementable primitive.
- Semantic depth between foreground/relational/comprehensive layers is real (each page-shell type is a real, distinct component — see Part A), but nothing yet expresses the *spatial* relationship (shared axis, asymmetry, void) between a page's primary content and its own peripheral/relational content.

**Conclusion: not already implemented.** This is the actual remaining M5.0 scope, addressed below without duplicating any existing page shell.

### Compositional Contract

One new primitive, `DistrictField` (`src/components/composition/DistrictField.tsx`), plus one new stylesheet, `src/styles/district-composition.css`. Contract:

- Two semantic roles only: `primary` (required) and `peripheral` (optional). No district name, no per-district boolean (`isWork`/`isArt`/…) anywhere in the prop surface or the CSS.
- One shared, district-agnostic emphasis state: `density: "concentrated" | "moderate" | "dense"` — DESIGN_SYSTEM.md §11.7's own vocabulary (concentrated void / moderate information density / dense evidence), never a district identifier.
- `.district-field` is a **nested grid reusing the exact same column-count and gutter tokens as `.composition`**, at the same three breakpoints — this is what makes the primary/peripheral split share the platform's one architectural axis (§11.3) instead of inventing a second ratio system. No new breakpoint, margin, gutter, column-count, or color token is introduced anywhere in `district-composition.css` (mechanically enforced — see Validation).
- Below the 1024px breakpoint, both roles keep the inherited `grid-column: 1 / -1` and simply stack in DOM order — an ordinary consequence of the same grid mechanics, not a special compact-mode code path (§47 "lateral relationships may become vertical").
- At 1024px and above, each density value assigns a different dominant/peripheral column split and a different `row-gap` (using existing `--space-*` tokens only) — per §11.8, "No fixed dominant/peripheral ratio is approved," so the ratio is deliberately a function of the shared `density` state, not a single hardcoded constant. `density="dense"` additionally opens its peripheral zone one column early relative to `moderate`, a selective offset (§11.4 — "an ordinary part of the visual grammar... not automatically a Controlled Exception").
- `DistrictNav`'s horizontal padding (`src/styles/district-nav.css`) now reuses `--margin-compact`/`--margin-medium`/`--margin-wide` at the same breakpoints as `.composition`, closing the shared-axis gap named in the audit above.
- `DistrictField` never renders the CSS `order` property and never reorders its own children — `primary` is always the first DOM child, `peripheral` (an `<aside aria-label="Related">` complementary landmark) always the second, at every breakpoint and every density.

## Calibration Implementation

CSS/compositional calibration only, per the review's own required approach — no new component, no new Design System token, no new district-specific rule, no new motion, no M5.1 work.

**Root cause found during audit, before any CSS change:** the fixture's own section/sub-headings (`<h2>`/`<h3>`) carried no approved type-role class at all — plain browser heading defaults, not the architectural typography system, were what was actually rendering. This alone plausibly explains a meaningful share of finding #6.

**Changes, all in `src/styles/district-composition.css` (and `src/components/composition/DistrictCompositionFixture.tsx` for typography/content-level calibration only — the fixture's structure and abstract, non-real content are unchanged):**

1. **Void → legible edges (findings 1, 2).** `.district-field` now opens with `border-block-start: var(--line-hairline) solid var(--color-graphite-700)` plus `padding-block-start: var(--space-7)` — the same hairline weight/color `.global-header` and `.district-nav-list` already use for their own structural dividers, extending that existing chain of aligned hairlines down through the page heading into the field. The void above the field now has a visible starting edge instead of trailing into unmarked space.
2. **Peripheral latency, permanently (findings 2, 3, 6).** `.district-field-peripheral` now always carries `color: var(--color-mist-300); opacity: var(--opacity-latent);` — the exact pairing already WCAG-verified for the Metadata Rail's own Latent tier (`src/styles/tokens/opacity.css`, ≈4.88:1 contrast), never a new color. This is a permanent property of the *role*, not a density-specific or viewport-specific state (verified — see Tests below), so peripheral now reads as genuinely secondary through DESIGN_SYSTEM.md §11.6's own "peripheral latency," not through a border/card/panel/background, which the review explicitly ruled out.
3. **Three genuinely distinct spatial signatures, not three ratios (findings 3, 4).** `moderate` stays a flush split (the balanced default, §11.8). `dense` keeps and clarifies its one-column selective offset between primary and peripheral (§11.4) at both medium and wide. `concentrated`'s primary zone is now itself offset off the left edge (`grid-column: 2 / span …`, not `1 / span …`) at both medium and wide — void surrounds it on both sides — so it reads as a deliberately placed field (§11.1 controlled asymmetry) rather than merely less content flush at column 1. `moderate`'s row-gap is now a fluid `clamp()` literal (the same established pattern `.field-interval` already uses for compositional-scale void — not a new token) giving it an "editorial breathing" quality `dense`'s fixed, tighter interval deliberately does not share.
4. **Compact rhythm (finding 5).** Below 768px, `.district-field-peripheral` now gets its own `margin-inline-start`, `padding-block-start`, and leading hairline — a compact-scale trace of the same selective-offset/shared-axis grammar (§48 "Responsive asymmetry... may survive through unequal vertical intervals... selective edge occupation") that survives stacking without recreating desktop columns. This is replaced by real column position once peripheral becomes a column at 768px and above.
5. **Typography actually applied (finding 6).** Every heading and text node in `DistrictCompositionFixture.tsx` now carries an existing, already-approved `DESIGN_SYSTEM.md` §7 type-role class (`.type-h2`, `.type-h3`, `.type-body`, `.type-body-small`, `.type-annotation`) instead of unstyled default markup. The `concentrated` state's focal statement additionally uses `.type-display` (already approved for "threshold moments"/major anchors, `src/components/page-shells/PageShell.tsx` already uses it identically for `WorldThresholdShell`) so it reads as occupying the field with authority, not merely as a smaller amount of body text. No new typeface, size, or weight was introduced — every class used already existed in `src/styles/tokens/typography.css` before this package.
