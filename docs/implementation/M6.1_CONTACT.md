# M6.1 — Contact

## Status

**Partially Ready — Presentation Implemented / Mechanically Verified. Delivery Blocked.**

The complete, accessible Contact presentation and client-side validation are implemented and tested. Real message delivery is not, and cannot honestly be, implemented — no approved delivery destination exists anywhere in repository authority (see "Delivery Mechanism Audit" below). This is a genuine content/configuration gap, not an implementation failure.

## Authority

The visitor may identify a context... but should not be forced through a complex qualification process. **Required fields:** name, reply address, message. **Avoid:** mandatory phone number, marketing consent, budget interrogation before conversation, hidden direct contact information."
- `PLATFORM_SPECIFICATION.md` §18.3 — "Contact must be reachable globally. It may resolve to About while remaining a distinct direct visitor intention. Contact actions must use literal commitment labels."
- `PLATFORM_SPECIFICATION.md` §34 — "The contact experience must identify the recipient/practice, use clear message purpose/pathway where needed, label actions literally, state submission status, preserve entered information after recoverable failure where possible, avoid sales-funnel pressure, provide an alternate contact route when editorially approved, and remain accessible and low-friction. **Exact public contact details are a content decision.**"
- `IMPLEMENTATION_PLAN.md` §11, M6.1 — "Implement direct Contact, minimal required data, accessible forms where used, error preservation, confirmation, privacy-aware handling, and no sales-funnel theatrics."
- M2.10 (`docs/implementation/M2.10_FORM_FAMILY.md`) — `TextField`/`TextAreaField`/`Action`, reused here as their first genuine production consumer.
- M2.11 (`docs/implementation/M2.11_SHARED_STATIC_STATES.md`) — `UnavailableState`, reused unmodified for the honest deferred-delivery state.

## Delivery Mechanism Audit

Audited fresh for this task, directly against repository content:

- No email address appears anywhere in repository authority — `PLATFORM_SPECIFICATION.md` §34 itself confirms this is "a content decision," not an oversight.
- No server action (`"use server"`) exists anywhere in `src/`.
- No API route exists anywhere in `src/app/api/`.
- No environment-variable file (`.env`, `.env.example`, or otherwise) exists anywhere in this repository.
- No email-provider SDK or configuration exists in `package.json`'s dependencies.

**Conclusion: no real submission can currently succeed, truthfully, under any implementation.** Per this task's own critical rule — "Never make a form appear functional when no truthful delivery mechanism exists" — this package implements the complete, real, accessible presentation and validation, and an honest deferred state on a valid attempt, never a fabricated success.

## What Was Implemented

`src/components/contact/ContactForm.tsx`, a real, client-rendered (`"use client"`) form component, wired into `/contact` (`src/app/contact/page.tsx`) as its default content — rendered unconditionally, alongside (never replacing) the pre-existing M4/M5 dev-fixture demonstration blocks already gated behind their own query flags.

**Fields** — exactly `ABOUT_UNIVERSE_v1.1.md` §18's own required set, nothing more: Name (`TextField`), Reply email (`TextField type="email"`), Message (`TextAreaField`). No phone, company, budget, project-type, marketing-consent, or tracking field exists anywhere in this component — directly asserted by its own test suite.

**Validation** — real, client-side: all three fields required; email additionally checked against a real format pattern. Validation runs on submit (`onSubmit`, `preventDefault`), never blocking typing or silently disabling the submit control ("no disabled-submit mystery," this task's own instruction).

**Error presentation** — reuses `TextField`/`TextAreaField`'s own existing error anatomy (M2.10, unmodified): `aria-invalid`, a real associated `role="alert"` explanation, and the field's own persistent label — never color alone.

**Focus management** — on a failed attempt, focus moves to the first genuinely invalid field, in field order (name → email → message). This required extending `TextField`/`TextAreaField` with `forwardRef` (both additive, backward-compatible — see "Shared Primitive Changes" below), since Contact is the first real consumer needing to move focus to the actual native control after validation.

**Preserved values** — every field is a real, controlled React input; nothing is cleared on a failed validation attempt. Directly tested.

**Honest deferred delivery** — a fully valid submission attempt does not call any network function (there is none to call). It replaces the form with a real `UnavailableState` ("This message was not sent." / "Contact is not yet connected to a real delivery destination — this is a content/configuration gap (Milestone 6.6), not a rejection of your message. Nothing you entered was transmitted or stored."). This is not a fake error and not a fake success — it is the honest third state this task's own critical rule requires.

## Shared Primitive Changes

`TextField`/`TextAreaField` (`src/components/form/`) gained `forwardRef` — purely additive: every existing call site that doesn't pass `ref` is byte-for-byte unaffected (confirmed by the pre-existing M2.10 test suites, unmodified, still passing). This is the same "extend for the first real consumer" discipline M2.10 itself already established for `Action`'s own `type="submit"` addition (`docs/implementation/M2.10_FORM_FAMILY.md` "M2.5 Submit Integration").

## Accessibility

- Every field has a real, persistent, associated `<label>` (M2.10's own unmodified contract).
- Required state is explicit text ("(required)"), never color-only.
- Errors carry `role="alert"` and are programmatically associated via `aria-describedby`.
- Focus moves to a real, correct native control after a failed attempt — never a generic page-top jump.
- The submit control is a real `<button type="submit">`, keyboard-operable by default, never disabled without explanation.
- The deferred-delivery `UnavailableState` reuses M2.11's own existing, already-accessible structure.
- Reduced motion: no motion exists anywhere in this component to begin with.

## Responsive Behavior

No new breakpoint, no new responsive rule. `form.css` (M2.10, unmodified) already governs `.form-field`/`.text-field`/`.textarea-field` at every width; `UtilityPageShell` (M1.5, unmodified) governs the page.

## Content Boundary
