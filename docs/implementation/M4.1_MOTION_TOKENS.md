## Duration

`--motion-duration-immediate` (80ms) · `--motion-duration-fast` (150ms) · `--motion-duration-standard` (240ms) · `--motion-duration-deliberate` (360ms) · `--motion-duration-spatial` (520ms) · `--motion-duration-ambient` (6000ms).

Maps onto §4's Motion Hierarchy: immediate/fast → Feedback; standard → State Change; deliberate → Focus; spatial → Sequence/Record Passage; ambient → Environmental Animation (§21) — deliberately, drastically larger (`ambient` is more than 11× `spatial`), since §21 requires environmental cycles to be "long or irregular," not comparable in scale to interaction feedback.

## Easing

`--motion-ease-enter` (`cubic-bezier(0, 0, 0.2, 1)`, decelerate), `--motion-ease-exit` (`cubic-bezier(0.4, 0, 1, 1)`, accelerate), `--motion-ease-move` (`cubic-bezier(0.4, 0, 0.2, 1)`, standard in-place repositioning), `--motion-ease-progress` (`linear` — a progress/loading indicator should never imply false deceleration near completion).

The three `cubic-bezier()` curves are the same well-established "decelerate/accelerate/standard" family used across mainstream design systems — chosen specifically because every control-point Y value stays within `[0, 1]`, which is the mathematical property that makes a cubic-bezier curve incapable of overshoot/bounce/spring by construction (a Y value outside `[0, 1]` is what produces that visual effect) — verified directly, per curve, in `motion-contract.test.ts`.

## Distance

`--motion-distance-micro` (2px, press-scale nudges) · `--motion-distance-component` (8px, hover/approach-scale shifts) · `--motion-distance-record` (32px, the largest current/near-term local-passage distance) · `--motion-depth-near` (0.02) · `--motion-depth-district` (0.05).

Depth is represented as a restrained relative-scale delta (e.g. `scale(calc(1 - var(--motion-depth-near)))`), not translation — depth communicates Z-axis recession/approach, deliberately far from the prohibited "large global zoom" (§34); `0.05` is a 5% scale change at its largest.

## Recession

`--motion-recession-subtle` (0.9) · `--motion-recession-focus` (0.6) · `--motion-recession-overlay` (0.35) — an opacity/visual-presence multiplier, per §12.2's "lower opacity... reduces hierarchy without erasing context." Token values only, per this task's own explicit instruction — no Focus/overlay system exists yet (confirmed: `motion-contract.test.ts` asserts no `Focus`/`Overlay`/`Return`/`Modal`-prefixed file exists in `src/components/shell/`). No blur value is included — blur is explicitly optional/performance-sensitive per this task's own §A5, and no current consumer needs it.

## Stagger

`--motion-stagger-tight` (20ms) · `--motion-stagger-standard` (40ms) · `--motion-stagger-group` (60ms) — short per-item delay increments for a grouped reveal (§12.1: "related content should reveal as a composition"), all under 100ms so a visitor is never made to wait for a staggered group to finish appearing.

## Environment

`--motion-environment-amplitude-low` (4px) · `--motion-environment-speed-slow` (12000ms) · `--motion-environment-presence-low` (0.15) — token foundation only. No `@keyframes`, no `animation-name`, and no environmental loop exists anywhere in `motion.css` or consumes these values yet (verified directly at the source level) — exactly this task's own instruction not to "implement an environmental animation just to test disabling it."

## Initial-value rationale

Every value above is, per this task's own explicit authority ("exact values may be tuned through prototype testing while preserving the approved hierarchy"), an **initial centralized implementation value**, not a claimed-final design decision. The semantic hierarchy (names, relative ordering, family boundaries) is locked; the numbers are calibration-ready by the M4-A integrated human review and later prototype packages (M4.8–M4.10). This deliberately extends the "resolve now, tune later" posture to *every* family in this file — distinct from M2.1's "declared but empty until a real consumer exists" precedent (`opacity.css`), because unlike M2.1's unresolved Design-System *ranges*, the Animation System gives this package no range to preserve, only a hierarchy — and a temporal system needs internally consistent numbers to be testable and usable at all, even before every family (recession, environment) has a real first consumer.

## Hierarchy invariants

Tested directly (`motion-contract.test.ts`): duration is strictly monotonic (`immediate < fast < standard < deliberate < spatial`) with `ambient` more than 5× `spatial` (the "`<<`" requirement); stagger is monotonic and stays under 100ms; distance/depth are monotonic and restrained (`record` ≤ 64px, `depth-district` < 0.2); recession is monotonic (`subtle > focus > overlay`); every easing curve is provably overshoot-free.

## District-token boundary

No district-specific motion token (`--motion-work-*`, `--motion-research-*`, `--motion-lab-*`, `--motion-art-*`, `--motion-products-*`, `--motion-about-*`, `--motion-home-*`) exists anywhere in `motion.css` — confirmed directly. District-specific emphasis remains explicitly out of scope for M4-A, per this task's own §A8, deferred to Milestone 5 and later prototype packages.

## Reduced-motion boundary

M4.1 does not implement reduced-motion behavior — that is M4.2's exact, separate scope (Phase B, next). The one pre-existing reduced-motion rule (`globals.css`, M1-era) is confirmed untouched by this package; M4.2 reconciles it explicitly rather than this package touching it prematurely or creating a competing rule.

## Programmatic-consumer boundary

No TypeScript motion-constants module was created. No component in this repository drives animation programmatically yet — M4.2's capability hook (Phase B) reads `matchMedia` directly, not these token values, and M4.3 (Phase C) will consume these tokens purely through CSS `var()` references. Per this task's own §A7 ("avoid two independent token sources that can drift"), a TS module is deliberately deferred until a genuine programmatic consumer needs the same semantic vocabulary — CSS custom properties remain the single source of truth for now.
