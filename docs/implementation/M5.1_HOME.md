## Home Role

Home is implemented as the entrance to the platform, not a résumé homepage, portfolio grid, marketing hero, dashboard, card collection, generic "welcome" page, splash screen, or cinematic intro. The composition establishes, in order: identity (heading = the approved Central Brand Idea, not the word "Home"), orientation (the approved Positioning Statement), and district availability (six one-sentence thresholds) — nothing more is loaded on first encounter.

## Spatial Concept

Home does not use `DistrictShell` (structurally distinct, per the audit above) and is not forced through the six-district layout pattern. It consumes M5.0's shared compositional grammar directly through **one single `DistrictField` instance** (`density="concentrated"`, matching DESIGN_SYSTEM.md §70's "strongest concentrated void, low default evidence density"): the orientation statement is `primary`, and the six district thresholds are that same instance's `peripheral` (calibrated — see "Calibration Implementation"; originally a separate section below the field, which is what the first review flagged as reading like "hero, then navigation underneath"). The district list is the same shared grid the orientation zone belongs to, not a second one.

## First Encounter

The first viewport carries exactly three things: the signature (h1, Display voice, the Central Brand Idea), one orientation sentence (the approved Positioning Statement), and the six district thresholds with one clause each. No project lists, publications, catalogues, CV sections, archives, or filters are loaded — those remain district/utility territory. This satisfies the Design System's identity function ("resolved at first encounter, while retaining visible capacity for relation, depth, and further discovery") — the district thresholds are the visible "capacity for... discovery."

## District Entry

**Decision, made explicitly rather than silently:** the M4.9 Home↔Work threshold mechanism (`ThresholdLink`, `ThresholdIndicator`, `WorldTrace`, `thresholdKeys.ts`) is reused completely unchanged for Work — the one district with reciprocal arrival-side wiring — and is **not** generalized to the other five districts in this package.

Reasoning: `WorldTrace`'s own doc comment explicitly scopes itself to "Home <-> Work ONLY... not a mechanism for choreographing arbitrary route changes," and its CSS (`threshold.css`) hardcodes real positional percentages for exactly two trace positions — generalizing to six would require inventing five more relative positions along a shared trace axis, a genuine new spatial-design decision this package has no dedicated authority to make unilaterally, and `M4.9_HOME_THRESHOLD_PROTOTYPE.md` itself explicitly reserves that decision ("Milestone 5 decides the real, broader strategy once every district genuinely needs it"). The M5.1 IMPLEMENTATION_PLAN.md "Verify" bar is "all districts reachable," not "all districts have full first/repeated-entry choreography" — reachability is satisfied honestly by real canonical-route links. Using `ThresholdLink` (which marks a departure key) for a district with no reciprocal arrival-side consumer would be inert complexity presented as more than it is — the opposite of "no fabricated Home passage."

The other five links use `ActionLink` (`kind="route"`, M2.5) — the approved route-link control, giving them the same `.link`/`.type-label` visual treatment as Work's `ThresholdLink` (which now accepts an additive `className` prop for exactly this reason) without a fabricated arrival-side indicator.

## Calibration Implementation

CSS/composition changes only, per the review's own required approach — no new component, no new Design System token, no new district-specific rule, no new motion, no wholesale architecture replacement.

**Root cause (answers to the required pre-change audit):**

1. *Why did the six-district area read as a navigation list?* Because it was a structurally separate block — `<section aria-label="Districts">` was a sibling **after** `DistrictField`, not part of the same field. Two visually stacked blocks (a resolved statement, then an unrelated list) is exactly a conventional "hero + nav" pattern, regardless of how the list itself was styled.
2. *What structural relationship existed between the headline/orientation and the district field?* None beyond default document flow — no shared axis, no line, no offset relationship; only accumulated vertical whitespace (`.field-interval` + `.district-field`'s own top padding).
3. *Which HOME_UNIVERSE spatial relationships were missing?* Shared axes (§11.3), selective offset (§11.4), peripheral latency (§11.6) — the district list used none of them; it was a plain full-width grid with uniform cells.
4. *Could this be solved through Home-specific composition/CSS and existing primitives?* Yes — confirmed below.
5. *Was any new component genuinely necessary?* No. `DistrictField` already has exactly the role this needed: a `peripheral` slot with pre-built peripheral-latency and compact-inset treatment, unused by Home's first implementation only because the six thresholds were kept as a separate section instead of being passed into it.

**Changes:**

1. **(A, B, C) The six district thresholds are now `DistrictField`'s own `peripheral` content**, not a sibling section (`src/app/page.tsx`). This is the central fix: it replaces "two stacked blocks" with "one field, a resolved zone and a latent zone" — and it means the districts inherit, for free, M5.0's own peripheral-latency color/opacity treatment (`--color-mist-300` + `--opacity-latent`, unchanged) and compact-width inset/hairline (unchanged) — mechanisms that already existed but were unused by Home's first pass.
2. **(B, C) A real connecting axis line and alternating offset** (`src/styles/home.css`, new `.home-districts` rules): a `border-inline-start: var(--line-hairline)` runs the length of the list — a genuine structural trace marking that all six thresholds share one line of reference (§11.3 shared axes), not decoration. Every other entry (`:nth-child(even)`) gets an additional `margin-inline-start` — "alternating latent/resolved placement," one of the mechanisms the review itself named as acceptable — expressing controlled asymmetry (§11.1) without encoding a false permanent ranking (order stays Work-first only because Work is the one district with real reciprocal M4.9 wiring, not because of importance).
3. **(A) Tightened heading-to-field void, Home-only.** `[data-district="home"] .district-field { padding-block-start: var(--space-5); }` (was M5.0's own `--space-7` default) — a narrowly-scoped override in `home.css`, never touching `district-composition.css` itself. The hairline threshold from M5.0's own calibration is kept (still a real transition marker); only the void's *size* is tightened for Home, giving the signature and the field more of a continuous-composition feel.
4. **(E) Compact rhythm is now automatic, not separately built.** Because the district list is `peripheral` content, M5.0's own compact-width `.district-field-peripheral` treatment (inset + leading hairline, unchanged since the M5.0 calibration) now applies to it directly — compact Home retains a real trace of offset/rhythm instead of collapsing to a plain link list, without any new compact-specific CSS in this package.
5. **(D) Authorship — audited, not filled with invented copy.** Re-searched `PLATFORM_VISION.md`, `HOME_UNIVERSE_v1.1.md`, `DESIGN_SYSTEM.md`, package metadata, and repository content for an approved public-facing personal name or identifier. None exists — `PLATFORM_VISION.md`'s Approved Authorship Model (§16) states the platform must eventually "operate under the person's name," but supplies no name, title, or approved personal descriptor beyond the practice-level language already used (Central Brand Idea, Positioning Statement). Per this task's own explicit instruction ("If the governing documents genuinely do not contain the required public-facing personal identifier: STOP and report that exact content gap rather than inventing copy"), **no authorship anchor was added.** This is reported as a real content gap, not resolved here — see "Deferred" and the response accompanying this work.

**What was deliberately not done:** no card, panel, or colored background for any district; no fake "you are here" map marker or literal map UI; no permanent visual ranking of the six districts; no change to `DistrictField`'s prop API or `district-composition.css`; no change to `WorldTrace`, `threshold.css`, or any M4.9 file; no new breakpoint; no invented authorship copy.
