## Comparison

### Representative context

**Lab**, per this task's own explicit preference — Lab's approved interaction philosophy already covers versions/attempts/inputs/outputs/results/status, exactly the shape a Comparison needs. Fixture-labeled data only (`src/components/comparison/LabComparisonFixture.tsx`) — no real experiment claim is made anywhere.

### Common-reference architecture

`Comparison` (`src/components/comparison/Comparison.tsx`) is a real, semantic `<table>` — the simplest mechanism that satisfies "common reference points remain stable" *structurally*, not by convention: a table's rows are the same rows for both compared columns by construction, there is no way to render a row that exists on one side but not the other. Four shared rows (Input, Method, Result, Status) are used for every pair of Lab attempts in the fixture.

### Motion

None, deliberately. `comparison.css` declares no `transition`, `@keyframes`, or `animation` anywhere (confirmed by source contract) — per this task's own explicit law ("once aligned: settle into stillness. No continuous animation"), the correct amount of motion for a structure that must be compared while completely still is none. No auto-oscillating slider, no continuous travel, no scale change during inspection.

### Responsive behavior

`.comparison-scroll` (`overflow-x: auto`) lets the table scroll horizontally at narrow widths rather than being mechanically stacked into two separate, disconnected blocks — which would destroy the row-to-row reference the whole comparison depends on. The relationship survives 390px because the *structure* (one table, shared rows) never changes — only how much of it is visible without scrolling.

### M4.6 integration — a real consumer at last

M4.6's `ReturnContext.comparisonState` field existed only as a fixture-labeled placeholder until now. `LabComparisonFixture`'s "Save this comparison" button calls the real, unmodified `captureReturnContext` with a genuine `{ left, right }` pair; "Restore saved comparison" calls the real, unmodified `retrieveReturnContext` and re-selects both sides. No second comparison store was created — this is M4.6's own function, exercised for real for the first time.

## Trace

### Representative relationship

**`Research —tested-in→ Lab`** — the exact directional example `INFORMATION_ARCHITECTURE.md` §5.4 itself already gives as approved usage, confirmed present in `src/domain/records/fixtures.ts` (`fixtureResearchRecord.relationships`) since M3.1. No relationship was invented for this prototype.

### Data-driven, never decorative

The entire chain is real, unmodified M3.5/M3.3 code: `resolveRelationship` (M3.5) resolves the target through the actual registry and derives the label from the actual stored `CanonicalRelationshipType`; the destination is `resolveCanonicalRoute`'s (M3.3) own output, never a Trace-specific route. `Trace`'s source, `RecordTrace`, maps *only* over `listOutgoingRelationships(source)` — there is no code path capable of drawing a line between two records without a real stored relationship between them.

### The negative proof

`RecordTrace` given a record with `relationships: undefined` (`fixtureAboutRecord`, genuinely relationship-free since M3.1) renders nothing at all — proven directly by test (`container` is empty), not merely asserted in prose. No classification similarity, visual proximity, or "same theme" heuristic exists anywhere in this component that could fabricate a Trace.

### No new line token

`DESIGN_SYSTEM.md v1.1` approves the *name* `line-relationship-trace` but gives it no weight/color (per `geometry.css`'s own header comment) — M4.10 does not unilaterally resolve it. `Trace.tsx` reuses M2.4's already-resolved `.line-structural` primitive directly (confirmed by source contract), the same "reuse an already-resolved primitive rather than invent a new token value" discipline M4.5 already applied to `.plane`/`.frame`.

### Direction and label

`deriveRelationshipLabel(type, "forward")` (M3.5, unmodified) supplies the visible label ("Tested in") — real stored-type text, not invented category text. Reciprocal/reverse display already exists in M3.5's own `listIncomingRelationships`/`deriveRelationshipLabel(type, "reverse")`, unmodified and untouched by this package — M4.10 does not need to re-demonstrate it, only confirm compatibility (no new stored inverse edge exists anywhere).

### Canonical destination

The `Trace` link's `href` is exactly `resolveCanonicalRoute(target)` (M3.3) — the same canonical identity every other part of the platform uses, never a Trace-only presentation route.

## No decorative-network proof

`trace.css` contains no `@keyframes`, `animation`, or `transition` (confirmed by source contract) — no progressive line-drawing, no pulsing node, no auto-generated graph layout. The "line" is a single `.line-structural` border under real text, not an SVG/canvas network visualization.

## Reduced motion

Not applicable to either component's own code — no motion exists in Comparison or Trace for a reduced-motion preference to affect (see **Motion**/**No decorative-network proof** above). Both remain fully understandable with all CSS disabled, since meaning is carried entirely by real text/table structure.

## Keyboard / touch

Comparison's attempt pickers reuse M2.6's `RadioGroup` unmodified — full keyboard/touch support inherited for free, no new control was built. Trace's destination is a real `next/link` — Tab, Enter, and touch activation all work identically to any other link in the application. No hover-only disclosure exists anywhere in either component.

## Fixture

`src/components/comparison/ComparisonTraceFixture.tsx` composes `LabComparisonFixture` and `TraceFixture` under one new, additive `?motion-fixture=m4c` value (`src/lib/motion/fixtureGate.ts`, extended the same way M4.4 already extended it for `m4b`) — mutually exclusive with the `m4a`/`m4b` fixtures on the same `/contact` route, no new route added. Per this task's own explicit instruction (§C18), this package — unlike M4.8/M4.9 — uses a `/contact` fixture rather than real page wiring, since no real Comparison feature and no real record-relationships display region exist on any canonical-record page yet; the fixture nonetheless consumes entirely real M3.5/M4.6 data and functions, never simulated stand-ins.

## No Sequence-system scope creep

This package implements exactly Comparison and Trace, per `IMPLEMENTATION_PLAN.md` §9's own list — no general Sequence system, no graph database abstraction, no recommendation engine. `RecordTrace` is a plain scan over an already-loaded record's own relationships, the same scale M3.1's `registry.ts` already operates at.
