## Starting-state audit

No Focus, Recession, or overlay implementation existed anywhere in the repository before this package — confirmed directly (M4.1's own `motion-contract.test.ts` already asserts no `Focus`/`Overlay`/`Return`/`Modal`-prefixed file exists in `src/components/shell/`, and a fresh search of `src/components/` found no such directory anywhere else either). `--motion-duration-deliberate` and `--motion-recession-focus`/`--motion-recession-overlay` (M4.1) had zero consumers before this package — this is their first real use, exactly as M4.1's own report anticipated ("M4.4/M4.5 and later" for recession/environment application).

## One Focus system, not six

`src/components/focus/FocusRegion.tsx` (context provider) and `src/components/focus/FocusItem.tsx` (the individual concentratable item) are the entire mechanism. There is no `WorkFocus`, `ResearchFocus`, `LabFocus`, `ArtFocus`, `ProductFocus`, or `AboutFocus` — confirmed directly, no such file exists. All six semantic contexts in the fixture (below) render through these same two components; the only per-context difference is the content passed in and, for one context (Art), a single prop value (`recessionToken`) — never a second implementation.

## Focus is not routing

`FocusRegion`/`FocusItem` import nothing from `next/navigation`, call no router, and reference no canonical-record or route-resolver module — verified both by direct code review and by a source-contract test (`tests/tokens/focus-contract.test.ts`, "never imports next/navigation or a router... never references canonical record/route modules"). Focus is pure in-page React state: which one item, if any, within a region is currently concentrated. It is not a modal, not an overlay, not a new district, not a new canonical record, and does not touch browser-history state — all of that is explicitly other packages' territory (M4.5/M4.6/M4.7), composed on top of this primitive later, not built here.

## Recession-first architecture

Recession is the entire mechanism — there is no zoom, no enlargement of the focused object. `src/styles/focus.css` implements exactly one CSS rule family: `[data-focus-state]` toggles between `neutral`/`active` (opacity `1`) and `receding` (opacity `var(--focus-recession-opacity, var(--motion-recession-focus))`). No `transform`, no `scale()`, no `blur()`, no `perspective` appears anywhere in the file — confirmed directly and by test. Blur was considered per this task's own §A3 ("blur is optional... do not use blur if it materially harms performance or text legibility") and deliberately not used: Research/About reading content in particular must stay perfectly legible even while receding, and opacity alone already achieves "quiet surrounding material" without that risk. A restrained scale delta was also considered (`--motion-depth-near` exists for exactly this) and deliberately not used either — opacity alone is the smallest mechanism that satisfies the requirement, and avoiding any transform at all removes any risk of this reading as a scale/zoom effect, which this task explicitly and repeatedly prohibits being dramatic.

## Recession magnitude — a configuration prop, not a second token or a district selector

`FocusRegion` accepts an optional `recessionToken` prop (`--motion-recession-subtle` | `--motion-recession-focus` | `--motion-recession-overlay`, defaulting to `--motion-recession-focus`), set as an inline CSS custom property (`--focus-recession-opacity`) on the region's own wrapping element. Art's fixture instance passes `--motion-recession-overlay` (0.35) so its interface recedes most strongly, per this task's own §A9 ("Art: interface recedes most strongly; authored work remains primary") — every other context uses the default `--motion-recession-focus` (0.6). `focus.css` itself contains zero district-name selectors (confirmed by test) — the CSS rule is identical for every context; only the *value* the consumer supplies differs, and that value is always one of M4.1's three already-approved recession tokens, never a new one.

## Stable origin, no detached-node risk

Each `FocusItem` renders exactly one `<button>` that serves as both the opening trigger and, once active, the exit affordance — its label switches from `Focus: {label}` to `Exit focus: {label}` and `aria-expanded` reflects the real state. Because it is the same DOM node throughout (never unmounted, never replaced), the "stable origin" requirement (§A4) is satisfied by construction rather than by tracking a reference that could go stale: DOM focus never has to jump anywhere on open, and there is nothing to "return" on close because focus never left. `FocusRegion` still exposes an `origin: HTMLElement | null` value in its context (the element passed to `open()`) precisely so a composing consumer — M4.5's modal overlay, which *does* need to move DOM focus elsewhere and return it — can read a live, same-document element reference without this module needing to know what "return" means for a modal presentation. This is the one piece of API surface built specifically so "M4.5 can compose it" (this task's own §A2 instruction), without M4.4 itself needing the complexity a modal requires.

## Keyboard

The trigger/exit control is a real `<button>`, so Enter and Space already activate it identically to a click — no custom key handling was written (confirmed: no `onKeyDown` anywhere in either component, verified by source contract). Opening Focus establishes a meaningful, stable focus target: the same control the visitor is already on, now relabeled to describe the newly revealed content and how to exit it — never an unexplained jump. Tab and Shift+Tab are never intercepted; every sibling control (including other items in the same region) remains independently reachable regardless of which item is active, and no `tabIndex` override exists anywhere (confirmed by test) — this is the direct proof that non-modal Focus does not trap the keyboard, per §A5's explicit requirement.

## Touch / pointer

No behavior anywhere depends on `:hover`. The control is a native button activated by `click` (which covers pointer, touch tap, and keyboard activation uniformly) — no double-tap-to-hover, no precision gesture, satisfying §A6 directly.

## Reduced motion

No JavaScript branches on `useReducedMotion()` in this package — none is needed. The one CSS transition (`opacity`, `--motion-duration-deliberate`) is already collapsed to an imperceptible, still-real state change by the pre-existing, M4.2-reconciled `prefers-reduced-motion` rule in `globals.css`, exactly the same mechanism M4.3 already relied on for its own transitions. Recession, focused hierarchy, and exit all remain fully understandable under reduced motion because none of them depends on the *animation* — only its *duration* changes; the state (which item is active, which are receding, the exit control's label) is unconditional React/DOM state, not something that exists only mid-transition.

## No async settle — no cancellation registry needed

M4.2's `createMotionCancellation` was audited for use here and deliberately not consumed: every state change in `FocusRegion` is a single synchronous `setState` call with no timer, no `transitionend` callback, and no async work whose result could arrive late. Switching directly from one active item to another (or opening then immediately closing) is handled correctly by React's own synchronous state update — there is no stale-settle race to guard against, unlike M4.3's `InterruptionDemo`, which genuinely has a `setTimeout`. This conclusion is proven directly by test (`Focus.test.tsx`, "switching directly from one active item to another resolves to only the newly opened item").

## Static completeness

With all CSS transitions collapsed (reduced motion) or disabled entirely, every Focus state remains completely understandable from structure alone: `data-focus-state` and `aria-expanded` are always correct regardless of motion, the exit control's accessible name always describes the real state, and detail content is genuinely present or absent in the DOM (a React conditional render, not an opacity-zero element still occupying the accessibility tree) — never implied by animation alone, satisfying §A8 directly.
